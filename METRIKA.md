## Где смотреть

### Плоский список «действие → количество»

По скриншоту данные уже приходят: `element` — «Параметр события, ур. 1», а `btn-debug-toggle`, `lang-btn` и другие идентификаторы — его значения на уровне 2. Для таблицы без дерева:

1. В фильтре **«События» → «+»** задайте условие **«Параметр события, ур. 1» = `element`** (точное совпадение). Фильтруйте сами события, не визиты/людей с такими событиями. При нескольких целях дополнительно ограничьте события целью «Клики по интерфейсу».
2. В **«Группировка»** оставьте только **«Параметр события, ур. 2»**. Уберите цель, уровень 1 и уровни 3–5.
3. В **«Метрики»** оставьте **«Количество событий»**. «Посетители» можно убрать, если нужен только счётчик нажатий.
4. Если доступен переключатель вида таблицы, выберите **«Линейный список»**. При одной группировке вложенных уровней уже не будет.
5. Отсортируйте по количеству событий по убыванию и сохраните отчёт как «Клики по элементам».

Ожидаемый результат по предоставленному скриншоту: `btn-debug-toggle — 4`, `lang-btn — 2`, `theme-btn — 2`, `burger-btn — 1`, `closeDrawer — 1`.

Фильтр `element` обязателен: без него на уровне 2 смешаются значения `area`, `label`, `page` и других параметров. Для читаемых названий вместо идентификаторов используйте такой же отчёт с фильтром уровня 1 = `label`.

Это одна группировка по действию, а не полное отключение группировок: без единственной группировки получится только общий итог. Названия полей взяты из показанной структуры отчёта; расположение условий внутри закрытого меню фильтра может отличаться.

### Если интерфейс выглядит как на скриншоте «Параметры цели»

Уточнение по скриншоту от 14 сентября 2026: отдельного списка «Выберите цель» нет. Кнопка «Группировка · Цель \"Java Script Событие\", +5» задаёт структуру таблицы, а не выбирает конкретную цель. При появлении данных цели и их параметры нужно раскрывать в таблице под графиком. Если цель одна, отдельный фильтр для неё не нужен.

На скриншоте указано **«События за отчётный период: 0»**. Это означает отсутствие событий в текущем отчёте за выбранный период; по одному скриншоту нельзя определить причину. Создание цели само по себе не отправляет событие.

1. Выберите **«Сегодня»**. Метрика должна получить новые клики после публикации обновлённого `ui/metrika.js`.
2. Откройте опубликованный сайт, примите соглашение и нажмите смену темы, затем «Лабы» с паузой больше секунды.
3. Для диагностики откройте `https://ai-agents-demo.gkorobkov.ru/?_ym_debug=2`. В отладчике Метрики проверьте событие `ui_click` счётчика `112561962`; при проверке через консоль ищите `Reach goal`. Это проверка вызова, а не гарантия немедленного появления отчёта.
4. Если событий нет, проверьте публикацию актуального кода, блокировщики и фильтр «Не учитывать мои визиты». При включённом фильтре Яндекс рекомендует проверять в приватном окне.
5. После обработки событий обновите отчёт. В таблице раскройте цель и `label`; сравнивайте **«Количество событий»**. Пока событий 0, раскрывать нечего.

Для ограничения отчёта одной целью используется фильтрация событий (кнопка **«+» рядом с «События»**), а не кнопка выбора цели. Название конкретного условия зависит от версии интерфейса; закрытое меню на предоставленном скриншоте не показано.

Основание для диагностики: [официальная проверка цели](https://yandex.ru/support/metrica/ru/general/check-goal).

Пример события: `page=labs`, `area=Учебная страница`, `label=Копировать пример или шаблон`, `section=lab1`. `element` — стабильный идентификатор; `type` различает кнопку, ссылку и раскрытие раздела. Страница указывает место клика, а не его назначение.

Считаются клики мышью, касания и активация кнопок/ссылок клавиатурой, в том числе внутри учебного iframe. Это активация элемента, не подтверждение успешного API-запроса. Содержимое полей, сообщений, пользовательские URL и API-ключи в параметры событий не передаются. Неизвестные ссылки группируются как «Другая ссылка»; отдельные вспомогательные кнопки — по имени обработчика либо общей группе.

**Ограничения:** Метрика учитывает одну и ту же цель не чаще раза в секунду и ограничивает количество достижений за визит. Поэтому `ui_click` — аналитика взаимодействий, а не точный журнал каждого быстрого клика. Без согласия, при блокировщике или до публикации события не поступают. Скрытое содержимое чата и настроек остаётся скрытым в Вебвизоре.

Проверка после публикации: примите соглашение, с паузами больше секунды нажмите смену темы → Лабы → копирование примера. Проверьте `ui_click` в отчёте, выбрав сегодняшний день. Тесты разработки перехватывают запросы и не загрязняют рабочую статистику.
